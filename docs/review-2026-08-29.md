# Codebase review — 2026-08-29

Whole-repo review for best practices and security issues. Four parallel reviews (API
security, API code quality, web app, infra/config/deps); every finding verified against
source with `file:line` citations.

**4 high · 15 medium · ~30 low.** All high and medium findings fixed 2026-08-29;
the lows remain open. Areas verified clean at the end.

## High

### 1. Check-then-act races let concurrent requests corrupt state — and defeat refresh-token replay revocation

No optimistic locking (`BaseEntity` has no `version`), no `PESSIMISTIC_WRITE` anywhere.
Four verified instances:

- [x] **`auth.service.ts:112-133` — refresh rotation race.** Two concurrent refreshes of the
  same token both pass the `revokedAt` check and both mint live successors. The headline
  guarantee (replaying a spent token revokes the whole family) degrades to "two valid
  sessions" under concurrency — and no test asserts the family actually dies, only that the
  replayed token 401s.
- [x] **`absences.service.ts:310-326` — double approval double-counts leave quota.** Both
  concurrent approvals observe `pending`, both commit +1 to `LeaveBalance`. Same shape between
  `withdraw()` (:278-292) and a concurrent `decide()`.
- [x] **`attendance.service.ts:334-348` — double approval of a correction inserts two
  `AttendanceEntry` rows.**
- [x] **`absences.service.ts:199-241` — overlapping absences.** Two concurrent `create()`s
  both pass `assertFree()`; no DB constraint catches date overlap.

*Fix (done 2026-08-29):* all four flows now serialize on advisory locks
(`common/db/advisory-lock.ts`, namespaces `REFRESH_ROTATION_LOCK`,
`ABSENCE_CREATE_LOCK`, `ABSENCE_DECIDE_LOCK`, `CORRECTION_DECIDE_LOCK`) inside
`em.transactional`, following the existing `INSTALL_LOCK`/`EMPLOYEE_NUMBER_LOCK` idiom.
Refresh decides under the lock but revokes the family *outside* the transaction — a 401
thrown inside would roll the revocation back. A 30-second replay grace
(`REFRESH_REPLAY_GRACE_MS`) distinguishes a second tab's concurrent rotation from a stolen
token. Tests: family revocation asserted (`auth.e2e-spec.ts`), concurrent rotation mints
exactly one successor (`refresh-rotation.e2e-spec.ts`), concurrent approve/create pairs
asserted in `absences.e2e-spec.ts` and `attendance.e2e-spec.ts`. Still open: a `version`
column on `BaseEntity` for the remaining check-then-act flows (clock-in, logout).

### 2. There is no CI

- [x] `.github/` didn't exist; the monorepo's "green" claim was enforced by nothing.
  Playwright's CI-only config (`forbidOnly`, `retries: 2`, github reporter at
  `playwright.config.ts:22-25`) was dead code. All three suites are headless-capable and
  self-contained.

*Fix (done 2026-08-29):* `.github/workflows/ci.yml` — checks job (build, lint, typecheck,
unit tests) + e2e job (both suites, Playwright report uploaded on failure); actions pinned
to commit SHAs, pnpm via corepack from the root `packageManager` field.

### 3. Dev compose publishes everything on 0.0.0.0 with hardcoded, env-unoverridable credentials

- [x] `infra/docker-compose.yml` — Postgres `beacon/beacon` on 5432, MinIO on 9000/9001,
  unauthenticated Prometheus/Loki, Grafana `admin/admin` with
  `GF_AUTH_ANONYMOUS_ENABLED: 'true'`. Zero `${VAR:-default}` interpolation. On any shared
  network that's a live Postgres with known creds.

*Fix (done 2026-08-29):* every port binds `127.0.0.1`, credentials are
`${POSTGRES_PASSWORD:-beacon}`-style env-overridable with the dev defaults kept, Grafana
anonymous access removed. Still open: pin the `latest` image tags.

### 4. Dark theme: every primary button fails WCAG AA contrast

- [x] `Button.svelte:46-47`, `MonthGrid.svelte:82-84` — white text on
  `--bc-dark-accent #a88cdc` ≈ 2.8:1 and `--bc-dark-success #7fbe9c` ≈ 2.1:1 (recomputed from
  token hexes). Clock in/out, submits, approvals — the app's primary actions. Light theme
  passes.

*Fix (done 2026-08-29):* new fill tokens `--bc-*-accent-fill` / `--bc-*-success-fill`
(`#7559b8` / `#39755f` in dark, the light accent/success in light) — 5.4:1 at rest and still
≥ 4.5:1 under `hover:brightness-110`; `Button` fills and the MonthGrid today chip use them.
The plain accent/success tokens stay as-is because they read as *text* on dark surfaces,
where the darker steps would fail.

## Medium

**Security**

- [x] **CORS fail-open.** `main.ts:12-15` — `origin: CORS_ORIGIN?.split(',') ?? true` with
  `credentials: true`. With the `SameSite=Lax` refresh cookie, an attacker page on a sibling
  origin can `fetch('/auth/refresh', {credentials:'include'})` and read a fresh access token
  → account takeover. Fix: fail closed (`?? false`), refuse to boot in production without
  `CORS_ORIGIN`.
  *Fix (done 2026-08-29):* `corsOrigins()` in `main.ts` returns the parsed list, `false`
  when unset, and throws in `NODE_ENV=production` — the e2e suites run with `NODE_ENV=test`
  and pass `CORS_ORIGIN` explicitly, so nothing relies on the open default.
- [x] **`PASSWORD_THROTTLE` is dead code.** `throttle.ts:21-23` defines an `auth`-named
  throttle, but `ThrottlerModule.forRoot` registers only `default` (`app.module.ts:39`);
  verified against `@nestjs/throttler@6.5.0` internals, the named override is never
  consulted. Auth runs at 120 req/min/IP instead of the intended 10; `AUTH_THROTTLE_LIMIT` is
  inert. Fix: name the override `default` or register the `auth` tracker; add a test.
  *Fix (done 2026-08-29):* the override is stored under `default` — the one tracker the
  guard actually reads (`throttle.ts`, with the mechanics explained in a comment).
  `test/throttle.e2e-spec.ts` asserts the eleventh password attempt within a minute 429s.

**API correctness**

- [x] **`GET /timesheet` can 500 on concurrent first reads** (`attendance.service.ts:472-486`):
  `balanceOf()` find-then-creates and races the `@Unique` on `OvertimeBalance`. Apply the
  `ensureBalance` upsert pattern (`absences.service.ts:568-603`).
  *Fix (done 2026-08-29):* `AttendanceService.balanceOf` now upserts with
  `onConflictAction: 'ignore', onConflictFields: ['user']` and re-reads the winner, mirroring
  `ensureBalance` including the constructor-default columns upsert skips.
- [x] **`clockOut` / `decideCorrection` commit in two transactions**
  (`attendance.service.ts:93-106, :334-350`): entry commits, then `recomputeBalance` in a
  second transaction — a failed second flush leaves stale balance, retry conflicts. Wrap both
  in one `em.transactional`.
  *Fix (done 2026-08-29):* both wrap entry + `recomputeBalance` in one
  `em.transactional`; `recomputeBalance` (and everything it touches — `entriesBetween`,
  `scheduleFor`, `balanceOf`, `AbsencesService.coverageOf`) threads the transaction's fork
  through, per the existing fork-passing idiom.
- [x] **CSV export materializes every row** (`reports.service.ts:128-145`): full row array in
  heap before the "streaming" writer starts. Stream per-user rows.
  *Fix (done 2026-08-29):* `attendanceRows` returns a lazy `csvRowsOf(folded)` generator;
  the controller already streamed whatever iterable it was given, so the rows are now
  produced one at a time as the socket drains.
- [x] **`week()` makes 7 schedule queries** (`attendance.service.ts:196-220`): one `findOne`
  per day; the batched fetch + in-memory `scheduleInForce` already exists
  (`reports.service.ts:423-431`, `schedules.ts:20-27`).
  *Fix (done 2026-08-29):* `week()` loads every schedule row for the span in one query and
  resolves each day through the shared `scheduleInForce`, so the timesheet and the reports
  now share one effective-dating decision as well as one query shape.
- [x] **Missing indexes**: `users.manager_id/department_id/team_id`,
  `attendance_corrections.user_id/local_date`, `teams.department_id`, `invitations.email`,
  `documents.deleted_at` (every document read filters `deletedAt: null`),
  `sso_login_attempts.expires_at` (scanned on every SSO start). One `@Index()` + migration
  each.
  *Fix (done 2026-08-29):* `@Index()` added on all six entities and shipped as
  `Migration20260829120000`.

**Infra/deps**

- [x] **`pnpm audit` — 2 moderate:** esbuild ≤0.24.2 via `svelte-i18n` (needs a root
  `pnpm.overrides` to ^0.25), ajv via `@mikro-orm/migrations`/umzug (upstream bump).
  *Fix (done 2026-08-29):* root `pnpm.overrides` — `svelte-i18n>esbuild: ">=0.25.0"`

- [x] **Mutable `latest` image tags** in both compose files (MinIO, Mailpit, Prometheus, Loki,
  Alloy, Grafana) — pin exact versions.
  *Fix (done 2026-08-29):* pinned to current releases — MinIO
  `RELEASE.2025-09-07T16-13-09Z`, Mailpit `v1.31.0`, Prometheus `v3.14.0`, Loki `3.7.7`,
  Alloy `v1.19.2`, Grafana `13.2.0` — in both compose files.

**Web**

- [x] **Failed mid-session refresh strands the user** (`client.ts:49-51`,
  `session.svelte.ts:91-95`): refresh failure clears the in-memory token but nothing calls
  `session.clear()` — at 30-day cookie expiry the user sits in an authenticated shell where
  every request 401s. Wire a failure hook to `session.clear()`.
  *Fix (done 2026-08-29):* `client.ts` exposes `onRefreshFailure`; `SessionState` registers
  `clear()` on it in its constructor (the client cannot import the session module without a
  cycle). Regression test added to `session.svelte.test.ts`.
- [x] **Documents: failed detail load renders nothing** (`documents/+page.svelte:157-176` vs
  `:283-326`): the error only renders inside `{#if selected && detail}`, and on failure
  `detail` is `null` — blank panel, no retry, next click toggles it closed.
  *Fix (done 2026-08-29):* a third panel branch renders the error with a Retry button
  (`documents.detailRetry`, en + de) when the selection has no detail and is not loading;
  `loadDetail` is shared by row click and retry.
- [x] **People list refetches on every keystroke** (`people/+page.svelte:39-55`): no debounce,
  no stale-response guard — mirror `SearchField.svelte:76-93` (200ms + generation counter).
  *Fix (done 2026-08-29):* the people filter effect debounces 200ms with a generation
  counter, so a slow earlier response cannot overwrite a newer one.
- [x] **Settings deletes fail silently** (`settings/organization/+page.svelte:107-116,
  133-136`): three unhandled rejections with zero feedback, while the sibling add paths handle
  errors properly.
  *Fix (done 2026-08-29):* department delete, absence-type retire and holiday delete each
  catch, map the error and render an alert in their section (`departmentActionErrorKey`,
  `typeActionErrorKey`, `holidayActionErrorKey`).
- [x] **Dashboard/Reports tiles render "0:00"/"0" for failed or in-flight loads**
  (`+page.svelte:89,97`, `reports/+page.svelte:228-280`); `loadWeek` also never clears its
  stale error banner.
  *Fix (done 2026-08-29):* the Today tiles print `—` until `week` exists, the Reports tiles
  print `—` until the dashboard band has loaded (`dashboardReady`, backed by a new
  `loadingDashboard` state), the overtime tile gates on `attendance`, and `loadWeek` clears
  the error banner before each reload.
- [x] **Search deep link `?open=` is dead** (`search-query.service.ts:134` → the documents
  page never reads the param); the e2e test enshrines only the URL match
  (`tests/search.spec.ts:52-54`), not the document opening.
  *Fix (done 2026-08-29):* the documents page consumes `?open=` — it opens the matching

  `tests/search.spec.ts` now asserts the detail panel's heading appears, which is the part

## Verified clean

- **IDOR/tenant scoping:** every controller derives the tenant from `@CurrentUser()`; the
  full `@Public()` set (setup, register, login, refresh, SSO, accept, health) is legitimately
  credential-less or token-credentialed; no client-supplied organization id is trusted
  anywhere.
- **Injection:** no raw SQL interpolation (advisory-lock/aggregate `execute` calls are
  parameterized); Meilisearch filters escaped; email HTML escaped.
- **Crypto:** `SecretCipher` is proper AES-256-GCM (fresh 12-byte IV per encrypt, tag
  appended, key length enforced at boot); argon2id with dummy-hash timing equalization; all
  three token types are 256-bit random stored as SHA-256.
- **Storage:** object keys fully server-generated (`org/<id>/documents/<id>/<versionId>`) —
  no traversal or cross-tenant overwrite surface; 20 MB cap enforced twice; downloads are
  presigned URLs to visibility-checked keys.
- **SSO:** all token verification inside `openid-client` only; single-use hashed state with
  10-min TTL.
- **No committed secrets** anywhere (test fixtures only); `.gitignore` covers `.env*`.
- **Web XSS surface:** no `{@html}`/`innerHTML`/`eval`; access token memory-only, never in
  `localStorage`; client-only rule holds (no `+server.ts`); `session.can` gates match API
  enforcement.
- **i18n parity:** 503/503 keys en/de, placeholder sets identical.
- **DI seams:** zero runtime vendor-SDK imports in feature code; explicit entity registry;
  consistent error philosophy; no circular modules.

## Suggested order

Highs and mediums are done (fixes marked above, 2026-08-29). What remains is the lows, in
roughly this order:

1. Cookie hardening: `Secure` by default in production, reject `SameSite=none` without it
   (`refresh-cookie.ts`) — it pairs with the CORS fix already in.
2. Pin JWT `algorithms: ['HS256']` and drop `client.ts`'s silent API fallback.
3. `em.upsert` for the SSO settings upsert and the `ensureBalance`-style fixes for the
   remaining check-then-act flows (`version` column on `BaseEntity` still open).
4. The a11y/i18n odds and ends — live regions, `<html lang>`, `aria-pressed` on the filter
   chips, the four hardcoded strings.
